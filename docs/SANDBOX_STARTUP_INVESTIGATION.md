## Source-supported mechanism and confidence

The following primary sources were inspected directly:

1. Electron 44.2.0 sends startup data through `MaybeSendRendererStartupData()` during `ReadyToCommitNavigation()`, ahead of the corresponding commit. This is a navigation-channel ordering guarantee. [Pinned browser implementation](https://raw.githubusercontent.com/electron/electron/v44.2.0/shell/browser/api/electron_api_web_contents.cc).
2. `InitializeBindings()` supplies null when the renderer API service/startup-data conversion is unavailable. Its comment says initial empty documents are excluded by preload eligibility. [Pinned sandboxed renderer implementation](https://raw.githubusercontent.com/electron/electron/v44.2.0/shell/renderer/electron_sandboxed_renderer_client.cc).
3. The actual `ShouldLoadPreload()` predicate checks main-frame/devtools/subframe eligibility and webview exclusion; it contains no initial-empty-document check. The frame observer's initial-empty-document guard depends on an opener and therefore does not cover an ordinary top-level BrowserWindow. [Pinned eligibility implementation](https://raw.githubusercontent.com/electron/electron/v44.2.0/shell/renderer/renderer_client_base.cc), [pinned frame observer](https://raw.githubusercontent.com/electron/electron/v44.2.0/shell/renderer/electron_render_frame_observer.cc).
4. The sandbox bundle destructures `binding.startupData` before executing application preload scripts. Null at this point directly explains the observed exception. [Pinned sandbox initialization](https://raw.githubusercontent.com/electron/electron/v44.2.0/lib/sandboxed_renderer/init.ts).

The likely mechanism is early Runtime activation causing an initial main-frame context to be initialized before the navigation's startup data exists, followed by an inappropriate sandbox-bundle initialization attempt. Confidence is **high** that the controlled early Runtime operation triggers the reported pre-release failure in this fixture, and **moderate-to-high** in that specific initialization mechanism. No native stack or instrumented startup-data receipt establishes the complete runtime call chain yet.

Current V8 Runtime activation invokes `beginEnsureAllContextsInGroup()`, and Chromium's implementation forces main-world initialization. These support the hypothesis but were inspected on current branches, not the exact bundled revisions, so they are supplementary evidence only. [V8 source](https://raw.githubusercontent.com/v8/v8/main/src/inspector/v8-runtime-agent-impl.cc), [Chromium source](https://raw.githubusercontent.com/chromium/chromium/main/third_party/blink/renderer/core/inspector/main_thread_debugger.cc).
